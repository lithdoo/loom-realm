## 1. 目标、非目标与判断尺度

本轮不是第三轮「发现一个边界条件就加一层处理」。目标是对现有全部 RPGMap v1 交付链做一次**减法优先**的整理：消除重复路径、历史双协议、额外状态、跨层业务耦合和过度的本地工具可靠性承诺；保留用户可观察行为、必要的数据保护及现有框架 ABI，并让最终代码和测试成为唯一交付依据。

不在本轮新增 NPC AI、移动、对话、通用事件解释器、Battle 双 Actor、通用安装平台、在线热更新、第二套 Runtime/Frame/Renderer 或新的公共 API。既有实质性能力不因缩短代码而退化；性能优化与历史测试依赖须先取证再删除。

**每个保留的复杂机制应能回答三个问题：**它保护哪条已冻结业务语义或真实外部约束？去掉会在受支持使用方式下出现什么可复现失败？这项职责是否已由来源层、框架层或另一段代码承担？若回答不出，优先合并、删除或降级为本地使用说明，而非再创造抽象。不要用代码行数、单测数量或抽象数量作为单独目标。

## 2. 首先缩小本地 FSDB 工具的承诺

### 2.1 受支持的使用前提（替代旧的过度设计）

`essentials-v21.1-local` 是**单用户、人工触发、可由合法原始素材重新生成**的本地测试示例，不是多用户数据库、部署安装器或不停服升级系统。使用者先退出游戏及其他重导入/Presentation 同步进程，再运行一次重导入；并发执行、运行中热替换和异常断电后自动修复**不属于 v1 支持范围**。脚本应在入口及 README 明示此前提，不能声称具备并发安全或跨平台原子切换。

仍必须保证三项最低数据安全边界：① **候选完成验证前绝不删除/移动旧正式库**；② **发现未处理备份就拒绝覆盖或删除**；③ **失败不能把未验证候选宣布为可用正式库**。原始 Essentials 来源永不由该工具删除。可正常捕获的安装/后验错误，尽力恢复原库；进程被强制终止时保存备份和明确人工恢复路径即可，**不承诺所有崩溃点自动恢复**。

### 2.2 最小切换实现

单一安装函数只负责：确认正式根最多一个 `[FSDB]*`、候选根恰一个 `[FSDB]*`，候选已完成数据和 Presentation 校验；拒绝预存备份、异常正式目录或跨文件系统；有旧库则 `rename(old, fixedBackup)`；`rename(candidate, target)`；对正式根再验证；成功删除备份。正常抛错时先确保不覆盖备份，撤下未验证候选（可保留诊断目录），再尽力 `rename(backup, original)`；若恢复失败，**保留原始备份并报出确切路径**，不再层层吞异常。初次安装无旧库，失败时不假造恢复备份。

`fixedBackup` 必须位于固定、gitignored 的 `.local/essentials-v21.1-reimport/` 工作区，不与正式目录内的 `[FSDB]*` 并排；两个 rename 之间可暂时无正式库，不宣称零停机。开始前若已有备份：**停止、提示先人工检查和恢复，不做自动猜测/接管**。`play.bat`/验证入口遇遗留备份或不完整正式库应拒绝启动，并给出备份/正式/候选路径、简短人工恢复指引；不主动改动文件。人工恢复应先关闭相关进程、辨识唯一旧备份与正式目录，再按提示将备份移回原名；不提供自动覆盖不明来源目录的快捷开关。

应删除生产路径的 `recovery.json`、五阶段 journal、PID/目录锁及自动清理/接管、`simulateCrash` 参数、开机 `recoverReimport` 自动修复和围绕不再支持的所有中断排列所写的测试；按实际引用移除无用 `recover-reimport.mjs`。**不要为了这次简化再造一套新的锁、通用事务类或恢复协议**。保留少量有价值测试：候选校验失败旧库未动、正常替换、正常异常恢复旧库、初次安装失败不造假、备份存在时拒绝、入口对不完整库拒绝，以及不触碰无关用户文件。

`--force` 若保留，仅代表用户明确允许以已验证候选替换现有正式库，不能在验证前删库；如果实际 CLI 不需要该选项，则删除死参数并同步批处理和帮助文本，不留下两套语义。明确告知：无自动并发保护意味着违反单实例前提时不保证安全，这不是需要继续补丁修复的「遗漏」。

### 2.3 Presentation 只保留一个写入者

生成器或 staging 准备只建立 `[resource]Presentation` 必要目录/元信息，不再在 `init-fsdb.mjs` 逐个复制 Map JS、Map CSS、page CSS 的内容。修改**现有** `syncMapPresentation({ repoRoot, exampleRoot, runBuild, checkOnly })`：非 `checkOnly` 模式支持 staging 缺失的目标文件并写入，正式 `checkOnly` 仍严格拒绝缺失；尽量复用已有 build 输出及源/dist 校验，避免同一轮先复制源码、再编译、再复制编译结果。保留正式使用者所依赖的同步 API 与已证明必要的单文件写入安全，不无故改变其其他调用者。流程只需「一次构建→一次同步→一次 checkOnly→一次候选完整性校验」。

## 3. Runtime：收敛规则，不扩大架构

**不引入**泛型 StateMachine、TransactionManager、事件总线、第二个 Runtime 或通用 Actor 层。优先在现有函数中做局部整理：

1. 一个易读的「能否接受操作」判断集中当前 Frame 是否结束、是否切图/NPC 准备/运动/事件忙碌；只在确有不同语义时单独判断，不让各输入回调自行拼装略有差异的条件。
2. 一条 RenderDomain 提交屏障：准备期加载/验证/容量检查先结束；仅成功调用 `createRenderDomain/replace/update` 后更新已提交事实。**真实 Domain 命令失败立即终止，后续 Step/Bridge/resize/输入均不能继续提交**。现有 resize 后仍可能执行 `startHere()` 的执行链应连同该屏障一起改正；不能加一个局部 if 就算整体收敛。
3. 一条 Frame 结束与资源释放路径：Input listener、Domain、viewport 订阅、step/resize timer 只清理一次；正常、异常、取消都走它。保留取消优先级和迟到工作无权提交。
4. `setNPC` 的互斥与提交前复核使用一个明确不变量；准备阶段已做的规范化不得无缘由地第二次完整 map/normalize。若必须复核，说明哪个真实共享状态可在 await 后变化，只针对该变量复核。
5. `RPGMapHandler` 和默认 `mapDefinition` 继续共用同一 Runtime；`WeakMap<Frame,...>` 等内部桥接如确有兼容理由可保留，不因「抽象多」机械删除。已公开 Builder/Handler/Error/type 与 Frame/Content/RenderDomain/Hostra ABI 不变。

重点针对真实场景测试「NPC 加载中输入」「prepare 失败旧场景仍可用」「resize Domain 抛错时落点恰为 Bridge」「传送与取消并发」「主动命令 fatal 后 reject 且 Frame 失败」「终止后 Domain 调用次数不增加」。不要对每个布尔状态排列组合造测试矩阵；测试不变量与典型交错即可。

投影代码先移除 `_previous` 等无效参数和无调用者分支。固定 overscan 是否能替代 `4→3→2→1` 搜索，应在典型地图、最大支持视口、Bridge 切层、滚动和真实消息预算下比较正确性、实际帧率及重建次数；若收益不足则采用最小固定方案，若搜索是达成容量/画面要求的必要条件则保留并用注释解释，**不为缩短代码牺牲大地图可用性**。

## 4. Browser：单一数据合同与单一 Sprite 集合

先全仓搜索运行时代码、测试 fixture、示例以及打包的实际输入，确认旧 `chunks/tileVisuals` 协议是否仍被**当前受支持消费者**使用。若仅旧测试/演进遗留使用，迁移测试数据到唯一 v1 `tiles` 输入后，删除 Browser 旧协议的分支、相关 validator/展开函数及无调用者兼容；测试应保留旧 M14/M15 所证明的实际瓦片、autotile、层深、Camera 和错误行为。若存在必须保留的外部调用者，先提供证据并将其作为明确兼容边界，不能直接删除。

将 Sprite 的准备、引用、拥有权、释放及 accepted/desired 集合统一为**一套内部条目集合**；Player 是根下约定的首个子 Sprite，具有单独的 motion 语义，其余为静态 NPC，不能为此修改 Renderer 节点结构或增加公开属性。消除 `_desiredSprite` 与 `_desiredSprites`、`extraSprites` 产生的平行维护；保留 Player 运动合法性、NPC `motion:null`、scene/visual/bridge 对齐和逐帧相机坐标约定。删除多 Sprite 不能泄露图片，也不能出现 stale decode 或残影。

瓦片增量缓存、资源 ref-count、异步取消代次、自动瓦片动画及已有 Browser 资格诊断**不是默认删除项**。仅在调用方/测试/性能数据证明重复、无效或可由现有机制替代时删减；不要为了简化而退回每帧整图绘制或让旧图异步解码覆盖新图。重试次数/状态字段/诊断计数作为「审计候选」而非预定删除目标。Browser 真实画面与 `mapEntered` 同步提交仍是两个不同的验证事实。

## 5. 数据生成、示例和验证的单一所有权

- **来源清单即独立事实来源**：复用已有 `lib/source/manifest.mjs` 的原始文件目录、大小与 SHA-256 等来源证据，核对输入 Map 清单与输出 Map key；不要因担心生成器与自身 manifest 同时漏图就再造第二个 Oracle 平台。原始 Canonical/RMXP 取证与 v21.1 Oracle 不得删掉。
- **只在正确层校验**：Importer 校验全部输入/输出结构、引用与必要的资源事实；本地候选验证检查正式产物和 Presentation 可用，按需验证来源映射。若声明使用清单的 `sha256` 来证明完整性，实际执行哈希比较；可在写入时增量计算，避免无必要地每次启动扫描全部资源。单纯检查 size 不能宣称内容哈希已通过。
- **Map21 固定八桥仍需严格整页 fail-closed**：一个权威固定规格/来源证据供生成器、验证器和测试引用，不在三个位置手写三份易漂移表；拒绝额外 Ruby/动态条件/未知命令，保留 `mapId/eventId/pageIndex` 可定位诊断；仅此固定源做行为等价转换，不扩张通用 Ruby 解释器。
- **示例数据由示例拥有**：`loomrealm-local-guide`、Map66 的位置和选择 `NPC 01` 等演示决策不能成为通用 Essentials 生成器的无条件常量。若采用本地 staging adapter 增补 `[struct]NPC`，必须确保它使用确实存在且合法的资源，且增补结果与生成清单/验证器一致；否则仅在确有证据时选择来源自身存在的 NPC，不伪造素材。通用验证器检查 Schema 和引用，本地消费者的存在性另由示例集成测试检查，不再全局硬编码单个 Guide。
- **删除重复而非弱化断言**：例如八桥属性测试、坏页拒绝、缺图与引用、非法 NPC、完整 Map 集合仍应有明确覆盖；可以共享 fixture 构造和权威数据，但不能让生成结果作为自己的唯一预期。

## 6. 全局减法审计：保留、删除、待证明三类

审查整个 **RPGMap 交付 Diff**，包括 `game-libs/map`、`tools/fixtures/essentials-v21.1`、两个 Essentials example、根 scripts/package、受影响测试/文档；不要求无关 monorepo 或 Battle 功能重构。逐段寻找：（a）同一协议两种表示；（b）同一数据由两个模块写入；（c）两个状态表达同一生命周期；（d）测试专用分支进入生产；（e）未用参数、死常量、过期兼容；（f）重复全量扫描/编译；（g）仅为不受支持极端情况建立的框架；（h）生成器与消费者职责反转；（i）文档要求比业务目标更强导致反向造抽象。

每个候选按以下标准处理，不需形成庞大报告：

| 分类 | 判断 | 动作 |
| --- | --- | --- |
| 删除/合并 | 无受支持调用者；职责重复；来自已撤回的可靠性承诺；行为可用现有单一路径覆盖 | 删除代码及对应无效测试，保留必要业务行为测试，给出短证据。 |
| 保留 | 来自真实外部 ABI、明确业务规则、可复现资源生命周期要求或性能测试证据 | 保留，必要时加一条解释注释，不再加包裹抽象。 |
| 待证明 | 可能是性能优化、历史调用者或边界策略，尚无执行证据 | 先运行最小针对性测试或仓库引用检索；无法证明则本轮不动，不能把猜测当阻塞。 |

**不能删除的底线**：Renderer 同域已删除 key 不可复用；可预测容量失败须在调用 Domain 前拒绝；真实 Domain 抛错后 fail-stop；Frame 取消/迟到异步隔离；NPC 唯一身份、整批占格与阻挡；Map21 静态转换安全；候选校验与旧库备份；不泄露受限 Essentials 素材。这些是必要约束，不意味着要为每项各建一套通用抽象。

## 7. 实施次序与文档治理

在现有 `agent/rpgmap-v1-end-to-end` 分支操作；保护未提交工作，获取最新 `origin/main` 并确认 Battle 等新增文件影响，**不要重建分支、不要推送到 main 或强制推送**。以完整 Diff 而非单个补丁 commit 为审查对象。实施顺序：

1. **文档先收敛**：修改旧实施计划第 3–5 节、闭环状态与 README，明确本地工具从自动恢复降为人工恢复前提，移除已过期的「计划新增测试命令／已全部执行」矛盾文字；主方案和公开 API 不随意改写。本文是减法决策，不是另一份 API 规范。
2. **先删双写与过度工具**：简单 FSDB 替换、启动检查、Presentation 唯一写入者；更新少量对应测试。
