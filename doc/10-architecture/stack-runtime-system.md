# 栈式运行系统

> 层级：系统架构  
> 状态：Active Design  
> 稳定程度：Evolving  
> 主要定义：调用栈、Frame 生命周期、激活周期和输入目标的设计思路  
> 依赖：[系统架构总览](./system-overview.md)  
> 最近复核：2026-07-29

## 1. 设计目标

栈式运行系统为模块子系统提供简单、可推理的调用关系：当前系统可以暂时调用另一个系统，被调用系统结束后，调用者恢复并获得结果。

## 2. 职责

- 根据入口创建初始 Frame；
- 维护唯一的后进先出调用栈；
- 执行调用、暂停、激活、返回和关闭；
- 决定当前普通输入目标；
- 为 Frame 签发激活周期标识；
- 处理初始化失败和子系统异常退出；
- 向渲染端发布调用栈镜像。

## 3. 非职责

- 不保存地图、菜单、对话或战斗状态；
- 不执行子系统内部 Tick；
- 不生成业务 Scope；
- 不解释调用参数和返回值中的业务字段；
- 不从 DOM 推断当前活动系统。

## 4. 核心概念

### Frame

Frame 表示一次子系统调用实例，而不是一个进程。即使未来一个进程承载多个 Frame，调用身份仍由 Frame 表示。

### Activation

Activation 表示 Frame 的一次活动周期。Frame 首次激活以及从子调用恢复时，应获得新的 Activation，用于隔离暂停前的迟到输入和状态消息。

### Stack

调用栈只记录系统调用关系：

```text
[map]
[map, menu]
[map, menu, dialog]
```

子系统内部状态始终留在子系统内部。

## 5. 生命周期

概念状态：

```text
starting
→ active
↔ suspended
→ closing
```

失败可以发生在初始化、活动或关闭阶段。精确状态转换、错误和幂等规则由正式生命周期契约定义。

## 6. 调用原则

- 只有当前栈顶可以发起普通调用或返回；
- 被调用者完成必要初始化后，调用者才进入暂停；
- 新 Frame 入栈后获得普通输入权；
- 下层暂停 Frame 可以继续保持可见；
- 返回时先清理当前 Frame，再恢复调用者；
- 调用建立成功与业务结果返回是两个不同阶段。

## 7. 故障原则

- 初始化失败的目标 Frame 不应进入正式活动栈；
- 栈顶子系统异常退出时，可以生成失败结果并恢复调用者；
- 初始 Frame 异常退出时，会话失败；
- 非栈顶子系统异常退出意味着调用链已损坏，第一阶段会话失败；
- 关闭必须有有限期限，超时后由进程监督模块强制终止。

## 8. 与其他系统的关系

- 通过通信系统发送生命周期和栈通知；
- 通过通道管理为 Frame 建立子系统与渲染端的数据连接；
- 不参与数据面中的普通输入和 Scope 内容；
- 使用存储系统提供的公共游戏包上下文解析初始子系统。

## 9. 扩展方向

未来可以评估：

- 一个进程承载多个 Frame；
- 子系统进程池；
- 可选后台或 Sidecar 系统；
- 多主栈或更一般的 Frame Graph。

这些扩展不得在第一阶段契约中被隐式引入。
