# 存储与内容系统

> 层级：系统架构  
> 状态：Active Design  
> 稳定程度：Evolving  
> 主要定义：只读游戏包、内容索引、Repository、资源和路径安全  
> 依赖：[系统架构总览](./system-overview.md)  
> 最近复核：2026-07-29

## 1. 设计目标

存储与内容系统为程序主系统和模块子系统提供安全、只读、按需的静态内容访问，同时隔离逻辑资源身份与本机物理路径。

## 2. 内容层次

```text
游戏包目录
├── 游戏清单
├── 入口文件
├── 静态数据
└── 资源主体
        ↓
安全包上下文
        ↓
轻量 Catalog
        ↓
模块 Repository
        ↓
不可变业务内容 / 资源描述
```

## 3. 游戏包

第一阶段游戏包是普通只读目录：

- 根目录存在统一游戏清单；
- 清单引用唯一入口文件；
- 入口指定初始子系统和 JSON 参数；
- 所有路径必须限制在包内；
- 不执行包内脚本或本机二进制；
- 运行状态、缓存和日志不写回游戏包。

## 4. 公共加载与业务加载

程序主系统只负责公共加载：

```text
读取清单和入口
→ 校验格式、版本和路径
→ 检查初始系统可解析
→ 建立只读包上下文
→ 启动目标子系统
```

目标子系统负责业务加载：

```text
验证调用参数
→ 使用 Catalog / Repository 定位内容
→ 按需读取和校验
→ 生成首次 Client State
→ 报告 ready
```

主系统不应根据 `system` 名称猜测地图、人物或其他业务字段。

## 5. Catalog

Catalog 是轻量内容目录，保存稳定逻辑 ID、类型、内容位置和版本元数据。

Catalog 不应保存：

- 全部地图 Tile；
- 全部业务记录主体；
- 图片字节；
- 会话状态；
- Client State。

## 6. Repository

Repository 是模块内部的按需内容访问边界，负责：

- 通过 Catalog 定位内容；
- 异步读取与解析；
- 局部 Schema 校验；
- 同 ID 并发请求去重；
- 进程内缓存；
- 返回不可变结果。

Repository 不负责业务 Tick、调用栈、Client State 投影或 DOM。

## 7. 资源模型

Client State 只携带逻辑资源 Key 和必要的内容版本：

```text
resourceKey + contentVersion
```

渲染端通过受限资源接口获取 MIME、版本和资源主体。图片字节不进入业务 Runtime Snapshot 或 Scope Tree。

资源接口的最终归属仍需在契约层冻结：可以由平台资源服务提供，也可以由子系统授权接口提供，但不能暴露任意文件系统访问。

## 8. 路径安全

所有物理路径必须：

- 使用包根目录相对路径；
- 规范化后仍位于包内；
- 拒绝绝对路径、URL、盘符和 UNC；
- 拒绝 `..` 越界；
- 拒绝符号链接、junction 或等价逃逸；
- 限制文件大小、记录数和递归深度。

所有内容都视为不可信输入。

## 9. 校验策略

启动和完整验证是两个不同操作：

- `start` 只加载建立会话所需内容；
- `validate` 遍历全部强引用并尽可能报告所有问题；
- 未访问内容可以在启动时延迟深度加载，但不应逃过完整验证。

## 10. 第一阶段 FSDB

第一阶段地图子系统使用 FSDB 保存地图、Tile、人物和资源定义。FSDB 是当前内容格式和参考实现，不自动成为所有未来子系统必须使用的公共存储接口。
