# 第一阶段设计待办

## 1. 文档目的

本文档记录 LoomRealm 第一阶段地图运行时原型尚未确定的设计问题。

这些问题会直接影响地图数据、角色移动、碰撞、Portal、状态同步与前端渲染，因此应在进入对应实现前完成决策，并将最终结论同步更新到相关设计文档。

本文档是待办清单，不代表其中的建议已经成为最终方案。

## 2. 最高优先级待办

### 2.1 坐标与移动模型

- [ ] 确定地图逻辑坐标使用格子坐标还是像素坐标。
- [ ] 确定玩家权威位置保存格子坐标还是像素坐标。
- [ ] 确定移动采用格子移动还是自由像素移动。
- [ ] 确定角色在两个逻辑位置之间是否使用渲染插值。
- [ ] 确定转向与移动是否为两个独立动作。
- [ ] 确定同时按下多个方向时的处理规则。
- [ ] 确定一次移动未完成时是否接受下一次移动输入。

当前优先评估的方向：格子逻辑移动，前端使用像素插值表现移动过程。

### 2.2 地图更新与移动时序

- [ ] 确定运行时使用固定逻辑 Tick，还是在输入消息到达时立即处理。
- [ ] 确定输入、移动、碰撞、Portal 检测和状态同步的执行顺序。
- [ ] 确定长按方向键时的重复移动规则。
- [ ] 确定移动动画进度由运行时管理还是由前端管理。
- [ ] 确定运行时同步逻辑位置还是逐帧像素位置。
- [ ] 确定地图切换期间是否暂停输入和逻辑更新。

### 2.3 Tile 索引规则

- [ ] 确定 Tile 索引从 `0` 还是 `1` 开始。
- [ ] 确定 Tile 在图集中的排列和索引计算规则。
- [ ] 确定是否存在专用的空 Tile。
- [ ] 确定空地图位置使用特殊索引，还是允许缺少对应记录。
- [ ] 确定地图是否必须完整保存每个坐标的 Tile 数据。
- [ ] 确定 Tile 索引越界时的错误处理方式。

当前优先评估的方向：索引从 `0` 开始，按从左到右、从上到下的行优先顺序排列。

### 2.4 `map.tile` 存储格式

- [ ] 比较逐格记录、按行记录和二维数组三种存储方式。
- [ ] 评估不同格式对 AI 修改、Git Diff、文件规模和运行时加载的影响。
- [ ] 确定第一阶段是否使用完整网格或稀疏网格。
- [ ] 确定地图坐标重复和缺失时的校验规则。

当前优先评估的方向：第一阶段测试地图规模较小，优先采用每格一条 JSONL 记录。

### 2.5 碰撞规则

- [ ] 确定第一阶段按目标格判断碰撞，还是使用角色碰撞盒。
- [ ] 确定地图边界是否默认不可通行。
- [ ] 确定 `blocked` 是否只表示完全不可通行。
- [ ] 确定 Portal 所在位置能否同时标记为阻挡。
- [ ] 确定角色视觉尺寸和逻辑占用范围之间的关系。
- [ ] 确定碰撞失败后角色朝向是否仍然更新。

当前优先评估的方向：玩家占用一个逻辑格，目标格被阻挡时拒绝移动，地图边界始终视为阻挡。

### 2.6 Portal 触发与地图切换

- [ ] 确定 Portal 在玩家进入触发格、完成移动后还是主动确认时触发。
- [ ] 确定目标位置是否允许位于另一个 Portal 区域。
- [ ] 确定目标位置是否必须为可通行位置。
- [ ] 确定地图切换期间输入如何处理。
- [ ] 确定如何避免切换后立即反向触发 Portal。
- [ ] 确定地图切换完成后发送完整状态还是增量状态。

当前优先评估的方向：玩家完成一步移动并进入 Portal 区域后自动触发；目标位置不得越界、阻挡或位于 Portal 区域。

## 3. 次级设计待办

### 3.1 项目入口

- [ ] 确定 `realm.project.json` 的正式职责。
- [ ] 确定项目格式版本字段。
- [ ] 确定项目 FSDB 路径的表达方式。
- [ ] 确定初始地图和玩家角色的引用方式。
- [ ] 明确哪些配置不得写入项目入口。

项目入口应保持最小，只承担项目启动和入口选择，不保存地图内容或运行时状态。

### 3.2 最小权威状态

- [ ] 定义第一阶段运行时状态的最小字段集合。
- [ ] 确定玩家移动中间态是否属于权威状态。
- [ ] 确定前端只保存哪些临时视觉状态。
- [ ] 确定状态版本的递增时机。
- [ ] 确定首次连接、重连和地图切换的完整同步规则。
- [ ] 确定增量同步失败后的恢复规则。

当前优先评估的方向：逻辑格位置属于权威状态，动画插值进度属于前端临时状态。

### 3.3 通用事件分类

- [ ] 确定用户动作、运行时通知、日志和故障的基本分类。
- [ ] 明确前端只发送归一化动作，不发送原始 DOM 事件。
- [ ] 明确事件与状态的边界。
- [ ] 明确哪些一次性消息不需要状态持久化。
- [ ] 明确事件处理失败时如何报告。

事件协议保持通用，不围绕地图、人物或 Portal 增加大量业务 RPC 方法。

### 3.4 数据与资源引用规则

- [ ] 确定实体引用使用 FSDB Key、文件名还是完整限定标识。
- [ ] 确定资源引用使用文件名、相对路径还是稳定资源 Key。
- [ ] 确定引用是否区分大小写。
- [ ] 确定文件扩展名是否属于资源标识的一部分。
- [ ] 确定数据 Key 重命名后的引用更新规则。
- [ ] 确定 `map.tileset`、`map.portal`、`tile.set` 与资源之间的校验规则。

### 3.5 校验与错误模型

- [ ] 定义校验问题的严重级别。
- [ ] 定义稳定的错误代码。
- [ ] 确定错误是否包含文件路径、数据 Key 和字段路径。
- [ ] 确定项目加载遇到错误和警告时的行为。
- [ ] 确定错误如何通过运行时通信返回前端。
- [ ] 确保错误信息能够支持编辑器定位和 AI 自动修复。

第一阶段至少应能明确表达以下问题：

- Portal 引用了不存在的地图；
- 地图坐标越界或重复；
- Tile 索引超出图集范围；
- 默认出生位置或 Portal 目标位置被阻挡；
- Tileset 或人物图片资源不存在或尺寸不合法。

## 4. 暂缓设计的内容

以下内容不属于第一阶段设计待办，除非当前原型证明无法绕开：

- Tile 属性库；
- 多地图层；
- Autotile；
- 地形类型；
- 动态地图实体；
- NPC 和地图事件；
- 存档数据库；
- 用户自定义数据结构；
- 插件数据和插件生命周期；
- 多角色控制；
- 通用动画状态机；
- 复杂碰撞和物理系统；
- 地图流式加载；
- 资源依赖图；
- 多人状态同步；
- 客户端预测和服务器校正。

## 5. 建议决策顺序

建议按以下顺序完成讨论和决策：

1. 坐标与移动模型；
2. 地图更新与移动时序；
3. Tile 索引规则；
4. `map.tile` 存储格式；
5. 碰撞规则；
6. Portal 触发和地图切换规则；
7. 最小权威状态；
8. 项目入口；
9. 数据与资源引用规则；
10. 校验与错误模型；
11. 通用事件分类。

坐标与移动模型是最优先决策，因为它会直接影响地图数据、碰撞、Portal、状态同步和前端渲染。

## 6. 待办完成规则

每一项设计待办完成后，应当：

1. 将最终结论更新到对应的正式设计文档；
2. 删除或更新与结论冲突的旧描述；
3. 在本文件中勾选对应待办；
4. 如存在明显取舍，补充架构决策记录；
5. 确认结论没有把第二阶段功能提前引入第一阶段。
