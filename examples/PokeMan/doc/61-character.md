# 人物

> 独立技术设计记录。不改写 `../DESIGN.md`。本文决定持久人物的 Content、好感，以及站位的三层取法。字段形状以外的对话、遭遇和角色卡实例留到各自模块。

归宿总表见 [数据落点](./60-data-placement.md)。

## Content 里的人物

一个持久的人一条 Content 记录。主角、家人、博士、宿敌、店主，以及以后可以收服的修行者，都是人物。进图时随机生成的混混、路霸不是人物，他们走遭遇模板。

人物记录只放这些：

- **身份**：`id`、名称。`id` 也是取资源的键。
- **描述**：职业、性格、经历。这是写死的文本字段，以后要加就再加字段。经历是作者写好的过去；这一局里发生的事记在剧情 State。
- **功能标签**：研究者、店主、家人这类标签，说明这个人在世界上的职责。

资源不写在这条记录里。所有种类的角色共用一套资源格式，用人物 `id` 去取。

人物都能成为角色卡。Content 不记录谁有成卡资格。能不能现在建立契约，由剧情和系统状态锁定。

## 好感

初始好感写在 Game Entry 的 `state.records` 里。新游戏时写入 Realm State。之后只认 State 里的当前值。

好感是一个整数。小于 0 就是敌对。阶段以后只按这个数划分，不另存一份态度标记。

## 站位

持久人物进图时按这个顺序取位置，取到就停：

1. **State 里的临时位置。** 有这个人的临时位置记录，直接用。
2. **事件位置。** 事件内容可以为同一个人定义「完成时的位置」和「未完成时的位置」。State 记录事件是否完成。按剧情顺序查看提到这个人的事件，取最后一条对应当前完成状态、并且写了位置的事件。
3. **默认位置。** 写在新游戏初始 State 里，是这个人开局站在哪张地图、哪一格、朝向哪边。
4. **不画。** 临时位置、事件位置、默认位置都没有，这个人当前不放上地图。

临时位置和默认位置是两条记录。临时位置盖住后面的结果；临时情况结束就去掉这条记录，下次再从事件位置和默认位置算。默认位置不被临时位置改写。

多条事件都写了同一个人时，只认剧情顺序上的最后一条匹配。某条事件只写了完成时的位置、而它尚未完成，这条事件不提供位置。

主角是玩家，不走这套 NPC 取位。混混、路霸由遭遇生成，不靠人物默认位置出现。

临时位置、事件位置、默认位置用同一种数据。静态位置是：

```text
type: "static"
mapId
x
y
direction
```

`type` 先只有 `"static"`，留给以后的巡逻等逻辑换别的类型。`mapId` 使用地图引擎的地图编号。`x`、`y` 是格子坐标。`direction` 使用地图引擎的朝向：`2` 下、`4` 左、`6` 右、`8` 上。

只有 `mapId` 和朝向还不能放上地图，缺了格子就不知道站在哪一格。

事件或临时位置也可以写成不在场，用来盖住后面的默认位置：

```text
type: "absent"
```

没有这条记录，和写成 `absent`，不是一回事。没有记录会继续往下找；`absent` 是已经取到的结果，人物当前不画。

## 进图时怎么画

地图引擎的 `struct.NPC` 仍然只有 `name` 和 `sprite`。World 进图时用上面的顺序得到这一张图上要画的人，用人物 `id` 取出资源，再把名字和图集交给地图。读档恢复的是存档里的临时位置、事件完成状态和默认位置，不是把初始文档再套用一次。
