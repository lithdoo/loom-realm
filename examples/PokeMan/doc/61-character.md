# 人物

> 独立技术设计记录。不改写 `../DESIGN.md`。本文决定持久人物的 Content，以及默认站位、初始好感放在哪里。字段形状以外的对话、遭遇和角色卡实例留到各自模块。

归宿总表见 [数据落点](./60-data-placement.md)。

## Content 里的人物

一个持久的人一条 Content 记录。主角、家人、博士、宿敌、店主，以及以后可以收服的修行者，都是人物。进图时随机生成的混混、路霸不是人物，他们走遭遇模板。

人物记录只放这些：

- **身份**：`id`、名称。`id` 也是取资源的键。
- **描述**：职业、性格、经历。这是写死的文本字段，以后要加就再加字段。经历是作者写好的过去；这一局里发生的事记在剧情 State。
- **功能标签**：研究者、店主、家人这类标签，说明这个人在世界上的职责。

资源不写在这条记录里。所有种类的角色共用一套资源格式，用人物 `id` 去取。

人物都能成为角色卡。Content 不记录谁有成卡资格。能不能现在建立契约，由剧情和系统状态锁定。

## 初始 State 里的站位和好感

默认站位和初始好感写在 Game Entry 的 `state.records` 里。新游戏时它们写入 Realm State。之后只认 State 里的当前值。

默认站位是这个人开局站在哪张地图、哪一格、朝向哪边。它不是另一种角色。主角是玩家，不占一条 NPC 站位。以后才出场的人，初始文档里可以没有站位；剧情发生时再写入 State。

好感是一个整数。小于 0 就是敌对。阶段以后只按这个数划分，不另存一份态度标记。

新游戏之后：

- 再次进入地图时，读 State 里的当前站位，不把初始文档再套用一次。
- 读档恢复的是存档，不是这份初始文档。

## 进图时怎么画

地图引擎的 `struct.NPC` 仍然只有 `name` 和 `sprite`。World 进图时读取 State 里这张图的当前站位，用人物 `id` 取出资源，再把名字和图集交给地图。
