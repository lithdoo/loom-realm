# PokeMan / 口袋从者 概念设计

> 状态：Draft
>
> 本文档是 PokeMan（中文名：口袋从者）的持续概念设计文档。后续关于游戏世界、核心循环、角色关系、角色卡、口袋陪伴、成长、战斗、叙事与系统边界的讨论，优先在本文档中逐步收敛和完善。

## 项目定位

**PokeMan** 是游戏英文名，中文名为 **口袋从者**。

口袋从者是 LoomRealm 中的一个独立 RPG 游戏实例，也是一个以真实游戏开发来检验 LoomRealm 核心架构与 `game-libs` 可用性的长期产品项目。

游戏在体验结构上对标 GBA 时代的宝可梦 RPG：以俯视角地图探索为主要世界空间，通过地图中的角色、事件与对话推进 RPG 内容，并通过独立 Battle 进入战斗体验。

但口袋从者并不采用“玩家自己就是宝可梦”的设定。游戏的核心角色关系是 **主公与从者**：玩家扮演主公，在世界中认识、接触、影响并最终收服不同从者，使其成为可以通过角色卡随身携带、互动并用于战斗的角色。

架构与库的验证服务于真实游戏开发，而不是反过来让游戏成为技术演示或测试夹具。设计决策首先应当回答“这是否让口袋从者成为更成立的游戏”，然后再观察这些真实需求如何验证和推动 LoomRealm 核心架构与可复用游戏库演进。

## 核心角色关系

口袋从者对经典宝可梦结构做如下转译：

- **主公**：玩家在世界中的主体身份，承担探索、交互、选择、收服与队伍组织；
- **从者**：可以被认识、培养、收服并用于战斗的世界角色；
- **角色卡**：从者被正式收服后的契约媒介、随身携带载体与使用凭证；
- **口袋从者**：被主公随身携带、能够持续陪伴和互动的已收服从者；
- **好感度 / 关系**：描述主公与角色之间的关系进展，是角色事件、对话变化、收服和后续成长的重要条件之一。

从者首先是世界中的角色，而不是一开始就属于玩家的战斗单位。玩家需要在地图世界中与这些角色发生真实关系，并通过对话、事件与对战逐步推进关系，最终满足条件后解锁对应角色卡。

因此，“收服从者”的核心含义不是单纯在战斗结束时执行一次捕获操作，而是把 **认识角色、发展关系、经历事件、解决冲突、建立契约和获得角色卡** 组织成一条完整的 RPG 过程。

获得角色卡也不是角色内容的结束。收服之后，从者既可以继续作为世界中的角色存在，也可以通过角色卡成为主公在旅行中随身携带、能够对话和互动的“口袋从者”。

## 核心玩法结构

口袋从者当前确认的核心玩法由三个主要能力构成：

- **Map**：承载 RPG 世界、地图探索、移动、场景、地点、NPC / 角色与世界中的空间关系；
- **Dialogue**：承载玩家与角色之间的交流、选择、关系推进、角色事件、随行互动与世界信息；
- **Battle**：承载独立的战斗玩法，使探索、角色事件、冲突和成长能够进入战斗并产生结果。

其中，**Map + Dialogue 构成主要的 RPG 世界体验，Battle 构成主要的战斗体验**。

三者围绕“发现、收服并带着从者继续冒险”形成基础循环：

```text
探索世界（Map）
      │
      ▼
发现角色 / 事件
      │
      ▼
交流与选择（Dialogue）
      │
      ├── 好感度与关系变化
      ├── 解锁新的角色事件
      └── 产生冲突 / 挑战 / 试炼
                    │
                    ▼
                战斗（Battle）
                    │
                    ▼
          结果返回角色与世界状态
                    │
                    ▼
            满足角色解锁条件
                    │
                    ▼
                获得角色卡
                    │
                    ▼
             放入口袋随身携带
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
随行 Dialogue / Event      后续 Battle
        │                       │
        └───────────┬───────────┘
                    ▼
               继续探索世界
```

`Map`、`Dialogue` 与 `Battle` 是支持游戏实现的可复用能力，但它们本身不是口袋从者的产品目标。真正的游戏体验来自这些能力之上的角色、关系、陪伴、世界、事件、成长、收服、故事以及玩家选择。

随着游戏开发推进，应通过真实玩法检验这些模块之间是否能够自然组合，并据此发现 LoomRealm Core 和 `game-libs` 中真正需要调整、补充或抽象的部分。

## 角色卡与收服

角色卡是口袋从者区别于传统宝可梦捕获表现的重要核心元素。

当前概念中，一个角色在世界里首先以独立角色存在。玩家与其建立联系后，通过好感度、对话事件、剧情事件、对战或其他角色条件逐渐推进解锁过程。当角色满足其收服条件时，玩家获得该角色对应的 **角色卡**。

角色卡至少表达以下事实：

- 玩家已经正式收服 / 获得该从者；
- 该从者进入玩家可以组织和使用的角色集合；
- 主公可以把该从者作为“口袋从者”随身携带；
- 角色在世界中的身份和关系历史并不会因为获得卡片而消失；
- 后续成长、对话、随行互动、事件和战斗仍可以继续围绕同一角色发展。

### 角色卡是收服结果，不是收服过程

角色卡当前首先被定义为 **从者被玩家正式获得后的关系凭证、契约媒介与使用载体**。

玩家不是通过“使用一张空白卡片并进行捕获判定”来完成所有收服。真正的收服过程发生在角色内容中：玩家先在世界中认识角色，通过 Dialogue、Event、Battle 和关系变化满足该角色自己的条件，之后才获得角色卡。

因此，角色卡负责回答的是：

> “这个从者现在是否已经正式进入玩家的可用与随行角色体系？”

而不是：

> “玩家通过哪一种统一捕获动作获得这个角色？”

获得角色卡标志着一个重要的角色关系阶段完成，但不意味着该角色的内容结束。已经收服的从者仍然可以继续拥有好感度变化、个人剧情、地图事件、随行 Dialogue、成长和新的 Battle 内容。

现阶段不预设角色卡等同于随机抽卡、商业化卡池或纯收藏图鉴。其首先是“从者被玩家正式获得并能够随身同行”的游戏内载体。

## 好感度与角色解锁

好感度是主公与其他角色之间的重要关系维度，但它不应被理解为单纯通过重复送礼堆高的数值条。

当前设计方向是让好感度与真实 RPG 行为共同决定角色关系：

- Dialogue 中的选择可以影响关系；
- 地图事件与角色事件可以改变关系；
- Battle 的挑战、协助或结果可以成为关系条件；
- 某些事件只有达到特定关系阶段后才会出现；
- 角色卡应当由“关系 + 事件条件”共同解锁，而不是只检查一个数值阈值；
- 收服后，好感度仍可以影响口袋 Dialogue、个人事件与后续能力成长。

一个典型从者的收服过程可以是：

```text
第一次在地图中遇见
        ↓
建立基本认识
        ↓
多次 Dialogue / Event
        ↓
好感度与角色状态发生变化
        ↓
触发专属事件或 Battle
        ↓
完成该角色的解锁条件
        ↓
获得角色卡
        ↓
成为可随身携带的口袋从者
```

### 收服路径由角色决定

不同从者不需要共享同一种固定的收服流程。角色自身的性格、处境、剧情和能力，应当决定玩家如何获得其角色卡。

例如可以存在：

- **关系型**：主要通过多次 Dialogue、正确选择和关系推进，最终由角色主动认可主公；
- **挑战型**：需要在 Battle 中战胜角色，证明实力后获得认可；
- **事件型**：需要帮助角色解决地图或剧情事件，在事件完成后解锁角色卡；
- **复合型**：先经历对话和事件，再进入 Battle，甚至需要多次相遇后才能完成收服；
- **条件型**：需要满足特定世界状态、已拥有角色、地点、时间或其他角色专属前置条件。

一个角色的收服过程可以像这样发展：

```text
角色 A：Dialogue → 好感度达标 → 专属事件 → 角色卡
角色 B：遭遇 → Battle 胜利 → Dialogue 认可 → 角色卡
角色 C：委托事件 → 好感度变化 → Dialogue 选择 → 角色卡
角色 D：首次 Battle 失败 → 地图再次相遇 → Event → 再战 → 角色卡
```

因此，口袋从者保留宝可梦式“不断发现并获得新角色”的收集驱动力，但不把所有角色压缩成统一的战斗后捕获流程。**收服本身就是角色 RPG 内容的一部分。**

## 角色本体、契约与不同显现

### 收服不让角色从世界中消失

一个角色被收服后，**角色本体仍然继续存在于地图世界中**。

角色可以继续待在原来的地点、承担原来的职业或剧情职责，并继续作为功能性 NPC、剧情角色和关系角色与玩家互动。收服并不是把一个世界角色从 Map 中移除，也不是把角色本人封进角色卡。

这一点允许同一个角色同时承担多种游戏职责。例如一个商店老板可以继续经营商店，同时又是玩家已经收服、能够随身互动并在 Battle 中使用的从者；一个关键剧情角色也可以在被收服后继续参与后续故事。

因此：

> **从者首先是持续存在于世界中的角色；收服使主公获得与其持续连接、随身同行和调用其力量的正式关系。**

### 契约是主公与角色之间的关系

当前概念中，“收服”更接近 **建立正式契约 / 获得角色认可**，而不是物理占有角色本人。

典型过程是：

```text
世界中的角色
      │
      │ Dialogue / Event / Battle / 好感度
      ▼
角色认可主公
      │
      ▼
建立正式契约
      │
      ▼
获得角色卡
```

角色卡记录和表达已经成立的从属 / 契约关系，使主公可以在旅行中持续与该从者保持联系，并在需要时调用其力量。

“契约”当前首先是设计概念，后续可以根据世界观决定游戏内的正式称呼、来源和规则。

### 角色卡是契约媒介，不是角色容器

角色卡不应被解释成“卡片里装着一个完整角色”，也不采用生物学或技术意义上的复制 / 克隆作为基础设定。

更合适的设计是：角色卡作为 **身份凭证、关系证明、持续连接和力量调用媒介**。它连接的是主公与角色之间已经建立的契约，而不是制造另一个角色本体。

因此角色卡至少可以承担：

- 已获得从者的身份凭证；
- 主公与角色之间正式关系的证明；
- 让从者以口袋形态随主公旅行和互动的媒介；
- Battle 中调用该角色战斗力量的媒介；
- 后续编队、成长和角色能力解锁的玩家侧载体。

## “口袋”与持续陪伴

### 口袋不是单纯的战斗卡组

“口袋从者”中的“口袋”首先表达一种核心玩家幻想：

> **主公能够把已经收服的从者带在身边，一起旅行、交流、经历事件并参加战斗。**

因此，放入口袋的从者不能只是 Battle 开始时才有意义的静态角色卡。被随身携带的从者应当在正常 RPG 探索过程中保持存在感，可以与主公进行 Dialogue，对地图、人物和事件作出反应，并参与属于自己的随行内容。

“把从者装进口袋”在体验上应该成立，但其世界观解释不是把角色本体缩小或复制后塞入容器，而是通过角色卡和契约，让从者的一种可交互显现持续陪伴主公。

### 同一角色的三个表现层次

当前设计可以把同一个已收服角色理解为三个不同的表现层次：

1. **世界本体（World Character）**
   - 角色真实存在于 Map 世界中的本体；
   - 保留职业、地点、功能性 NPC、剧情与社会关系；
   - 可以继续面对面进行 Dialogue 和 Event；
   - 不会因为被收服而从地图上消失。

2. **口袋化身（Pocket Manifestation，工作术语）**
   - 从者通过角色卡与契约陪伴主公旅行时的轻量显现；
   - 可以与主公对话、回应选择、评论环境和人物；
   - 可以参与随行事件、角色事件和探索反馈；
   - 不被视为另一个独立人格或克隆体，与世界本体属于同一个角色关系和角色状态。

3. **战斗化身（Battle Manifestation，工作术语）**
   - 通过角色卡在 Battle 中完整显现的战斗形态；
   - 承载该角色的战斗能力和 Battle 表现；
   - 不要求角色本体离开世界中的现实位置。

```text
                 同一个角色
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
      世界本体    口袋化身    战斗化身
    Map / NPC   Dialogue /    Battle
                 Companion
          │          │          │
          └──────────┼──────────┘
                     ▼
             同一关系 / 同一角色状态
```

“口袋化身”和“战斗化身”当前都是概念设计阶段的工作术语，后续可以根据世界观寻找更自然的正式名称。

### 口袋从者可以持续 Dialogue

已经放入口袋的从者可以成为玩家旅途中的持续 Dialogue 对象。

这种 Dialogue 与面对地图 NPC 本体的 Dialogue 有不同语境：

- **World Dialogue**：玩家面对角色本体时发生的现实世界互动；
- **Pocket Dialogue**：角色作为随身从者，在旅行过程中与主公发生的陪伴式互动。

例如一个已经收服的药店老板可以同时存在以下体验：

```text
地图里的角色本体：
“欢迎回来，需要什么药？”

口袋中的随行互动：
“你又跑到这种危险的地方来了？”
“前面那种植物有毒，最好绕开。”

进入 Battle：
通过角色卡显现完整战斗形态参战。
```

因此，收服后的角色不是从 Map / Dialogue 内容中“毕业”，而是新增了一个长期的随行交互维度。

### 随身编队同时是战斗编队和陪伴编队

“这次冒险要带谁”不应只是一道 Battle 数值优化题。

当前随身携带的从者可以同时影响：

- Battle 中能够调用的角色；
- 探索途中可以主动对话的角色；
- 对地点、NPC、物品与事件的特殊评论；
- 特定随行 Event 的触发；
- 某些探索信息、提示或角色专属选择；
- 角色之间可能产生的队内互动。

例如带着剑士、炼金师和学者进入遗迹时，不同从者可能对同一场景产生完全不同的反馈。这样，队伍构成同时拥有 **战斗意义、探索意义和角色意义**。

具体携带上限、卡组规模、是否存在卡册 / 卡包 / 卡匣等界面与世界观形式，后续结合实际 playable slice 和成长系统确定。

### 口袋化身与世界本体共享角色身份

为了避免出现“地图 NPC 和口袋里的从者像两个独立角色”的割裂，世界本体、口袋化身和战斗化身应当共享同一角色身份与核心关系事实。

原则上：

- 好感度不是三份；
- 收服状态不是三份；
- 核心角色剧情不是三套独立进度；
- 口袋中的对话可以感知世界本体已经经历的事件；
- 世界本体后续的对话也可以感知主公携带该角色经历的旅途和 Battle。

具体哪些状态属于角色长期事实、哪些属于一次显现的临时状态，后续在数据模型设计中进一步明确。

### 本体参战仍然成立

战斗化身是角色卡调用的默认解释，但并不意味着所有 Battle 都只能通过化身发生。

如果剧情中角色本体确实与主公同行、就在现场或主动参与事件，则可以直接以 **角色本体参战**。在 Battle 规则层面，两者可以共享同一套角色战斗数据和能力模型；区别主要存在于剧情与世界状态解释中。

这为未来剧情 Battle、同行角色和特殊事件保留了空间，而不需要为“本体”和“卡牌角色”建立两套完全不同的战斗系统。

### 收服后角色关系继续发展

获得角色卡不是角色内容的结束，而是角色关系进入新的阶段。

```text
未收服
  │
  │ 建立关系 / 完成条件
  ▼
获得角色卡
  │
  │ 放入口袋同行
  ▼
Pocket Dialogue / Event / Battle
  │
  ▼
深化关系
  │
  ▼
角色剧情、能力和角色卡继续成长
```

这意味着好感度在收服后仍然有意义。角色可以根据与主公关系的深化产生新的对话、个人事件、随行反应、剧情变化，以及未来可能的卡牌能力、战斗能力或表现变化。

这种结构也允许游戏反复利用同一批高质量角色：他们既丰富 Map 与 Dialogue 的世界内容，也丰富玩家旅途中的陪伴体验和 Battle 的可用阵容，而不需要为了扩大战斗角色数量而持续制造一批只用于战斗的角色。

## 养成方向

基于“世界本体持续存在 + 角色卡建立契约 + 口袋持续陪伴 + Battle 调用化身”的结构，养成不应被设计为一个与世界角色脱节的“卡牌复制体等级”。

当前更适合的方向是：

> **玩家养成的是与角色的关系、契约深度，以及主公能够调用和发挥该角色力量的程度。**

后续养成系统可以围绕以下层次继续设计：

- **角色关系成长**：通过 Dialogue、Event、共同经历和选择深化好感与关系阶段；
- **契约 / 角色卡成长**：随着关系和经历深化，解锁更完整的角色能力；
- **Battle 熟练与能力成长**：通过实际参战形成战斗层面的长期成长；
- **随行成长**：携带角色探索世界、触发 Pocket Dialogue 和专属事件，使陪伴本身成为成长来源；
- **主公成长**：提升组织、携带、调用和指挥从者的能力。

具体的 Level、属性、技能、突破、契约阶段等数值与规则尚未定型，后续应结合第一个真实角色和 playable slice 设计，而不是先建立一套脱离角色内容的通用养成框架。

## 核心设计目标

### 1. 建立“主公与从者”的核心幻想

玩家以主公身份进入世界。从者不是无人格的收集物，而是先作为世界中的角色被认识，再逐渐成为玩家可以正式收服、随身陪伴和使用的伙伴。

“获得一个新从者”应当既具有收集与成长的满足感，也具有完成一个角色关系阶段的 RPG 意义。

### 2. 让“口袋”产生真实陪伴感

玩家应当能够明确感受到：自己不是只携带了一组战斗数据，而是真的“带着从者们一起冒险”。

随身从者应通过 Dialogue、环境反馈、角色事件和 Battle 持续存在于玩家体验中，使“口袋从者”成为产品核心幻想而不仅是标题。

### 3. 保持地图 RPG 为核心体验

游戏继续以俯视角地图探索为主要空间形态。

玩家应能够在地图中自由探索，并能够自然理解道路、障碍、区域边界、建筑、场景入口以及不同地点之间的关系。

地图不只是背景，而应逐步成为承载角色、事件、遭遇、故事、收服、陪伴与成长的主要游戏空间。

### 4. 让 Dialogue 成为角色关系和陪伴的主要玩法

Dialogue 不只是文本展示，而应承担认识角色、表达玩家选择、推进好感度、解锁信息、触发角色事件、改变关系状态和表现随行陪伴等职责。

玩家与从者之间的关系必须能够通过具体对话和事件被玩家感知，而不是只在后台增加一个不可见数值。

### 5. 让 Battle 参与角色与世界推进

Battle 应当由探索、遭遇、角色事件、挑战或其他游戏情境自然触发，并在结束后将结果带回 RPG 世界和角色关系。

战斗可以是角色卡解锁条件的一部分，但不要求所有角色都必须通过“打败后收服”的单一路径获得。

Battle 的结果未来也应能够影响角色状态、好感度、成长、Pocket Dialogue 和后续事件。

### 6. 让收集建立在角色内容之上

口袋从者保留类似宝可梦的“不断获得新角色”驱动力，但收集对象是具有自身关系、事件、人格表达和陪伴内容的从者。

角色卡负责给玩家明确的“已经获得”反馈，而角色内容负责让这张卡具有意义。

同一个高质量角色应当可以同时服务于地图世界、Dialogue、剧情、功能性 NPC、口袋陪伴与 Battle，而不是为了增加战斗阵容必须持续制造一批只用于战斗的角色。

### 7. 延续 essentials-v21.1 的视觉与内容基础

PokeMan 初期沿用 `essentials-v21.1` 已有的地图与美术资源，使新游戏能够在一个已经成立的 GBA 风格 RPG 世界基础上开始设计。

现有资源主要作为口袋从者世界的起点，而不是限制。随着游戏内容扩大，可以逐渐形成属于口袋从者自己的区域、角色、美术与世界表达。

### 8. 保留完整 RPG 成长空间

口袋从者的长期目标是形成完整的 RPG 循环，而不仅仅是地图移动、对话或战斗模块的组合演示。

后续游戏体验可以围绕以下方向逐步发展：

- 主公身份与成长；
- 从者收集与培养；
- 好感度与角色关系；
- 角色卡、口袋与队伍组织；
- 随行 Dialogue 与角色陪伴；
- 地图探索；
- NPC / 从者对话；
- 角色事件与世界事件；
- 战斗；
- 区域探索与解锁；
- 世界状态变化；
- 故事推进。

这些能力不要求在第一阶段同时完成，但整体设计应允许它们自然加入，而不改变口袋从者的核心身份。

## 第一阶段体验目标

PokeMan 的第一个 playable slice 应优先证明最核心的产品循环，而不只是证明地图能够运行。

第一阶段目标可以围绕一个具体从者展开：

- 游戏能够作为独立实例进入；
- 玩家以主公身份进入一个完整的 RPG 地图场景；
- 玩家能够自然地进行四方向探索；
- 玩家在地图中发现一个尚未收服的角色；
- 玩家能够与其进行 Dialogue，并通过选择使角色关系发生可观察变化；
- 角色关系可以推进到一个事件或挑战；
- 该流程可以进入 Battle；
- Battle 结果能够返回 RPG 世界并影响角色状态；
- 满足条件后，玩家能够解锁并获得该角色的角色卡；
- 获得角色卡后，该从者成为玩家可用角色体系的一部分；
- 该角色本体仍然保留在地图世界中，并可以产生收服后的 Dialogue / 功能 / 剧情变化；
- 玩家可以把该角色放入口袋，在离开角色本体所在地点之后继续与其进行 Pocket Dialogue；
- 口袋中的从者能够至少对一个地图地点、事件或 NPC 产生随行反馈；
- 玩家可以通过角色卡在后续 Battle 中调用该从者的战斗化身；
- Battle 结束后，从者可以继续以口袋陪伴状态参与后续探索和对话。

如果这条链路成立，就形成了口袋从者第一个真正有产品意义的 vertical slice：

```text
Map
 → World Dialogue
 → Relationship
 → Event / Battle
 → Character Card
 → Pocket Companion
 → Pocket Dialogue
 → Map / Event
 → Battle Manifestation
 → Pocket Dialogue
 → 继续探索
```

它也会同时真实验证 LoomRealm 的 Map、Dialogue、Battle、Realm State、Frame / Runtime 控制流以及多个 `game-libs` 的组合能力。

## MVP 序章流程骨架

### 序章目标

MVP 序章不是把 Map、Dialogue、Battle 各自做成一个独立 Demo，而是让第一次接触口袋从者的玩家在一段连续流程里亲手理解以下核心事实：

- 玩家是以“主公”身份进入世界并组织从者关系的人；
- 世界中的人物可以与玩家建立角色卡连接，并成为玩家能够携带和调用的从者；
- 角色卡不会让人物本体从世界中消失；
- 角色卡能够让角色以战斗化身参与 Battle；
- 收服并放入口袋后，从者仍然能够持续 Dialogue、回应地图和陪伴玩家冒险。

序章在体验节奏上先直接借鉴 GBA 时代宝可梦的经典开局：**家中醒来 → 小镇 → 博士研究所 → 宿敌 → 初始关系 / 战斗教学 → 离开小镇开始冒险**，但将其中“选择初始宝可梦”的结构替换为口袋从者自己的“主角与宿敌互相建立角色卡连接”。

完整骨架如下：

```text
家中醒来
↓
探索小镇
↓
进入博士研究所
↓
认识 / 重逢宿敌
↓
博士介绍角色卡
↓
主角与宿敌互相建立并交换对方的角色卡
↓
第一次 Battle：使用对方的角色卡进行战斗
↓
回到研究所
↓
宿敌本体留在研究所
↓
玩家接受博士的外出任务
↓
离开研究所 / 小镇
↓
第一次 Pocket Dialogue
↓
口袋中的宿敌对地图环境产生第一次主动反应
↓
野外事件
↓
第二次 Battle：在真实 RPG 情境中调用宿敌卡
↓
Pocket Dialogue 回应战斗结果
↓
遇见新的潜在从者
↓
序章结束，进入正式冒险
```

### 第一幕：家中醒来

游戏从主角家中开始，尽量保留经典 GBA RPG 的熟悉感。

这一幕只负责让玩家进入世界并学习最基础的 Map 操作，不急于解释角色卡、契约或 Battle。

最低体验目标：

- 玩家在家中取得移动控制；
- 可以与少量家人或房间物件互动；
- 通过 Dialogue 得知博士正在找主角；
- 玩家能够从室内自然移动到小镇。

家人给出的主线信息应保持直接，例如“博士刚刚来找过你，让你去研究所一趟”。

### 第二幕：第一次探索小镇

玩家离开家后，可以在小镇内进行短暂自由移动，而不是直接传送到博士面前。

这一段负责建立一个真正可以探索的 RPG 世界，并提前埋下博士、宿敌和角色卡相关信息。

最低体验目标：

- 玩家可以探索若干建筑、路牌与 NPC；
- 2～3 个普通 NPC 能够进行基础 Dialogue；
- 某些 NPC 可以提到博士近期正在研究角色卡；
- 某些 NPC 可以提前提到宿敌也被博士叫去了研究所；
- 玩家最终自行进入博士研究所。

此处只制造兴趣，不完整解释角色卡规则。

### 第三幕：博士与宿敌登场

玩家进入研究所时，宿敌已经在场。

这一幕建立三个人物关系：主角、宿敌和博士。博士负责引导新系统；宿敌则成为玩家第一张真正有角色意义的卡，同时也是第一个长期陪伴角色。

基本节奏：

```text
玩家进入研究所
↓
博士欢迎
↓
宿敌插话
↓
建立主角与宿敌的竞争 / 熟识关系
↓
博士说明今天叫两个人来的原因
```

博士在序章中首先承担 **角色卡体系研究者 / 引导者** 的功能。

序章对角色卡的理论说明应尽量短，只需要让玩家理解：

- 人与人之间可以建立某种正式连接；
- 当关系成立后，可以形成对应角色卡；
- 持有角色卡可以与对方保持联系，并在需要时调用对方的力量。

角色卡的历史、能量来源、社会制度和完整世界观原理不需要在 MVP 序章解释。

### 第四幕：主角与宿敌互换角色卡

博士指导主角与宿敌完成第一次双向角色卡连接。

序章需要表现的结果是：

```text
玩家获得：宿敌角色卡
宿敌获得：主角角色卡
```

这里的“互换”不是简单交换某一张唯一实体卡，而是双方都获得代表对方的角色卡。其完整生成机制和世界观解释可以后续继续设计。

这一幕同时建立一个重要方向：**一个角色可以作为别人的从者存在，同时自己也可以拥有其他角色卡、组织自己的从者关系。** 因而“主公 / 从者”优先被理解为关系中的位置，而不是把世界人口划分成两个固定物种或阶级。

### 第五幕：第一次角色卡反馈

玩家获得宿敌卡后，应在进入 Battle 之前先得到一次明确的“获得角色”反馈。

MVP 不要求完整角色管理界面，但至少需要让玩家看到：

- 宿敌的角色身份；
- 角色卡已经正式获得；
- 该角色当前已经可以被放入口袋 / 使用；
- Battle 能力存在，但无需在此时展示复杂数值。

表现上可以有清楚的角色卡获得动画，并让卡片进入“口袋”。这一瞬间应建立玩家第一次“我获得了这个角色”的收集反馈。

### 第六幕：第一次 Battle——用对方的力量战斗

宿敌或博士提出立即测试角色卡，于是在研究所进入第一次 Battle。

这一战采用最具口袋从者辨识度的结构：

```text
现实中的玩家本人              现实中的宿敌本人
      │                             │
      │持有宿敌卡                   │持有主角卡
      ▼                             ▼

Battle 中：
宿敌战斗化身        VS        主角战斗化身
由玩家指挥                     由宿敌指挥
```

玩家因此能够直接观察到：

- 宿敌本人仍然在现实场景中；
- 玩家手上同时持有宿敌角色卡；
- Battle 中又出现了宿敌的战斗化身。

这场 Battle 的核心作用是通过玩法证明“角色卡不是把人物本人装进去”。

第一次 Battle 不追求复杂战斗深度，只需要完成最小闭环：

```text
进入 Battle
↓
角色显现
↓
选择基本行动
↓
移动 / 攻击 / 技能
↓
产生胜负
↓
退出 Battle
↓
回到研究所
```

Battle 应使用 `@loomrealm-game/battle` 已有的真实规则，而不是为了模仿 Pokémon 强行复制其菜单式一对一战斗。这里对标的是叙事和教学节奏，而不是要求 Battle 表现完全一致。

### 第七幕：Battle 后再次面对本体

第一次 Battle 结束后，玩家直接回到研究所，宿敌本体仍然站在那里。

这里通过很短的 Dialogue 再次强化：

> Battle 中出现的是通过角色卡显现的力量，而不是角色本体从现实世界中消失或被复制成另一个独立人物。

宿敌也可以通过对自己战斗化身的吐槽、评价玩家指挥方式等方式，让这个规则以人物性格自然呈现，而不是变成长篇教程文本。

### 第八幕：博士给予第一次外出任务

到这里玩家已经初步接触：

```text
Map
Dialogue
Character Card
Battle
```

接下来序章必须证明“口袋陪伴”。因此博士给玩家一个很小的镇外任务，让玩家离开研究所开始第一次真正外出。

任务本身不需要复杂，可以是：

- 去镇外调查某个地点；
- 帮博士取得某个物品；
- 寻找某个人；
- 确认某个异常事件。

关键剧情条件是：**宿敌本体暂时留在博士研究所。**

这样玩家与宿敌本体产生明确空间分离，为下一幕 Pocket Dialogue 建立必要条件。

### 第九幕：第一次 Pocket Dialogue

玩家离开研究所或走到镇外以后，宿敌第一次通过角色卡主动与玩家说话。

这是序章最重要的产品时刻之一。

玩家此时同时知道：

- 宿敌本人还留在研究所；
- 自己把宿敌卡带在口袋中；
- 即使离开宿敌本体，仍然可以和这个角色持续交流。

第一次 Pocket Dialogue 可以非常简单，例如宿敌确认连接是否成立、吐槽玩家或者提醒前方危险。

这一幕真正解释了“口袋从者”的核心幻想：

> **被收服的角色不是只在战斗开始时才出现，而是真的能够被主公带在身边一起旅行。**

### 第十幕：第一次环境反应

在第一次 Pocket Dialogue 之后，还需要至少一个由宿敌主动感知 Map 世界的反馈。

例如：

- 走到镇口时提醒前方区域危险；
- 看到某个 NPC 时主动评价；
- 经过某个地点时提到自己的经历；
- 发现某个物件时提出建议。

这一幕用来证明：

> **口袋从者不是一个远程通讯录，而是会和玩家共同经历当前世界的陪伴角色。**

### 第十一幕：第一次真正的野外事件

离开小镇以后安排一个非常小的 RPG 事件，使玩家第一次在非教学环境中使用已经携带的角色卡。

基本结构：

```text
进入镇外区域
↓
发生地图事件
↓
宿敌 Pocket Dialogue
↓
玩家回应 / 做出选择
↓
冲突升级
↓
进入 Battle
```

这场事件的重点不是剧情规模，而是把 Map、Pocket Dialogue 和 Battle 串成一个自然事件。

### 第十二幕：第二次 Battle——真实情境中的角色调用

第二次 Battle 与研究所教学战的意义不同。

第一次 Battle 是：

> “角色卡能不能工作？”

第二次 Battle 是：

> “我在真实冒险中遇到问题，并主动使用随身从者解决它。”

玩家通过宿敌角色卡再次调用其战斗化身，完成战斗后返回 Map。

Battle 结束后应立即有一次 Pocket Dialogue，让宿敌能够评价战斗结果、玩家的选择或者当前处境，从而证明 Battle 结果可以重新进入角色陪伴体验。

### 第十三幕：遇见新的潜在从者

序章结束前，玩家应当第一次遇到一个 **尚未收服的新角色**。

MVP 序章不一定需要完成这个角色的完整收服，只需要：

- 在 Map 中真正遇见对方；
- 发生一次有角色感的 World Dialogue；
- 玩家可以产生一个初步选择或关系变化；
- 对方暂时离开或因为条件不足无法立即获得；
- 口袋中的宿敌可以对这个新人产生一句评价或反应。

这一幕的作用是让玩家把刚刚学会的规则投射到整个世界：

> **世界中遇见的这些人物，未来都有可能通过关系、事件和战斗成为新的口袋从者。**

序章在这里结束，并把玩家推向正式的角色探索、收服与陪伴循环。

### 序章四阶段认知目标

整个 MVP 序章可以压缩成四个玩家认知阶段：

| 阶段 | 玩家应建立的认知 |
| --- | --- |
| 家 → 小镇 → 博士 | 这是一个可以自由探索和互动的 GBA 风格 RPG 世界 |
| 博士 → 宿敌 → 角色卡 | 世界中的人物可以与我建立角色卡关系并成为从者 |
| 第一次 Battle | 角色卡能够显现角色力量，而角色本体依然存在于世界中 |
| 离开研究所 → Pocket Dialogue → 野外 | 从者真的能够被带在“口袋”里持续陪伴、交流并参与冒险 |

序章完成后，玩家应已经亲手走过以下最小产品闭环：

```text
Map
→ World Dialogue
→ Character Card
→ Battle
→ 回到角色本体
→ Pocket Companion
→ Pocket Dialogue
→ Map / Event
→ Battle Manifestation
→ Pocket Dialogue
→ 发现新的潜在从者
```

MVP 后续细化应围绕这个骨架逐幕确定具体角色、地图位置、Dialogue、事件条件、Battle 内容和 Realm State 状态变化，而不是先继续扩大系统数量。

## 设计原则

PokeMan 后续设计遵循以下原则：

- **玩家是主公，从者是可被认识、建立关系并最终收服的角色。**
- **从者先是世界中的角色，之后才同时成为玩家持有的随行与战斗角色。**
- **“口袋”意味着随身陪伴，不只是战斗卡组。**
- **被放入口袋的从者能够与主公持续 Dialogue，并参与探索和事件反馈。**
- **收服不会让角色本体从地图世界中消失。**
- **功能性 NPC、剧情角色和可收服从者可以是同一个角色。**
- **世界本体、口袋化身和战斗化身属于同一个角色，而不是三个独立人物。**
- **三种表现共享核心关系和角色事实，避免独立状态产生人格割裂。**
- **角色卡是收服关系的核心载体，而不是一开始就假定为随机抽卡系统。**
- **角色卡表达收服结果，收服过程由具体角色内容决定。**
- **角色卡是契约、持续连接与力量调用媒介，不把角色本人当作被装入卡片的对象。**
- **普通 Battle 中角色卡调用战斗化身；角色本体在剧情需要时仍可以直接参战。**
- **好感度必须服务于真实角色关系和事件，并在收服后继续具有意义。**
- **随身编队同时具有 Battle、Dialogue、探索和角色内容上的意义。**
- **地图探索是 RPG 世界体验的基础。**
- **Dialogue 服务于角色、关系、陪伴、事件、选择与世界表达。**
- **Battle 是 RPG 世界中的冲突、挑战与成长机制，而不是孤立小游戏。**
- **收服路径允许由 Dialogue、Event、Battle 和角色专属条件共同构成。**
- **不同从者允许拥有不同的收服逻辑，不强制统一捕获流程。**
- **先形成可玩的“发现角色 → 收服 → 随身陪伴 → 战斗 → 继续陪伴”循环，再增加复杂系统。**
- **新增能力应服务于真实游戏体验，而不是为了展示技术能力。**
- **通过真实游戏需求验证 LoomRealm Core 与 `game-libs`，而不是围绕框架能力反向设计玩法。**
- **已有资源是起点，不是最终内容边界。**

## 当前非目标

当前阶段不以以下内容作为目标：

- 完整复刻传统宝可梦游戏的全部规则；
- 让玩家直接扮演从者；
- 把“收服”解释为角色本体从世界中消失；
- 使用写实的复制 / 克隆设定解释口袋或 Battle 中出现的从者；
- 把口袋仅仅设计成没有角色交互意义的战斗卡槽；
- 为世界本体、口袋化身和战斗化身分别维护三套互不相关的角色成长与关系状态；
- 一开始就完成完整战斗、队伍、属性和成长体系；
- 把所有角色都设计成同一种固定收服流程；
- 现在就确定角色卡、契约、口袋化身与战斗化身的完整世界观来源和正式术语；
- 现在就确定角色卡的完整编队、召唤或商业化规则；
- 为了 PokeMan 而提前设计与当前游戏体验无关的大量系统；
- 为了抽象而提前把所有 PokeMan 业务能力沉淀为新的 `game-libs`；
- 将 PokeMan 变成单纯的平台、框架验证样例或测试夹具。

PokeMan / 口袋从者首先应该成为一个真正的游戏，然后再逐步扩展为更完整的角色收集与陪伴 RPG。
