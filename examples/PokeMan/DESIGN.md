# PokeMan / 口袋从者 概念设计

> 状态：Draft
>
> 本文档是 PokeMan（中文名：口袋从者）的持续概念设计文档。后续关于游戏世界、核心循环、角色关系、角色卡、成长、战斗、叙事与系统边界的讨论，优先在本文档中逐步收敛和完善。

## 项目定位

**PokeMan** 是游戏英文名，中文名为 **口袋从者**。

口袋从者是 LoomRealm 中的一个独立 RPG 游戏实例，也是一个以真实游戏开发来检验 LoomRealm 核心架构与 `game-libs` 可用性的长期产品项目。

游戏在体验结构上对标 GBA 时代的宝可梦 RPG：以俯视角地图探索为主要世界空间，通过地图中的角色、事件与对话推进 RPG 内容，并通过独立 Battle 进入战斗体验。

但口袋从者并不采用“玩家自己就是宝可梦”的设定。游戏的核心角色关系是 **主公与从者**：玩家扮演主公，在世界中认识、接触、影响并最终收服不同从者，使其成为可以通过角色卡持有和使用的角色。

架构与库的验证服务于真实游戏开发，而不是反过来让游戏成为技术演示或测试夹具。设计决策首先应当回答“这是否让口袋从者成为更成立的游戏”，然后再观察这些真实需求如何验证和推动 LoomRealm 核心架构与可复用游戏库演进。

## 核心角色关系

口袋从者对经典宝可梦结构做如下转译：

- **主公**：对应玩家在世界中的主体身份，承担探索、交互、选择、收服与队伍组织；
- **从者**：对应可以被认识、培养、收服并用于战斗的角色；
- **角色卡**：对应从者被正式收服后的持有与使用载体，在功能上承担类似精灵球与宝可梦持有关系的核心位置；
- **好感度**：描述主公与其他角色之间的关系进展，是角色事件、对话变化以及角色卡解锁的重要条件之一。

从者首先是世界中的角色，而不是一开始就属于玩家的战斗单位。玩家需要在地图世界中与这些角色发生真实关系，并通过对话、事件与对战逐步推进关系，最终满足条件后解锁对应角色卡。

因此，“收服从者”的核心含义不是单纯在战斗结束时执行一次捕获操作，而是把 **认识角色、发展关系、经历事件、解决冲突和获得角色卡** 组织成一条完整的 RPG 过程。

## 核心玩法结构

口袋从者当前确认的核心玩法由三个主要能力构成：

- **Map**：承载 RPG 世界、地图探索、移动、场景、地点、NPC/角色与世界中的空间关系；
- **Dialogue**：承载玩家与角色之间的交流、选择、关系推进、角色事件与世界信息；
- **Battle**：承载独立的战斗玩法，使探索、角色事件、冲突和成长能够进入战斗并产生结果。

其中，**Map + Dialogue 构成主要的 RPG 世界体验，Battle 构成主要的战斗体验**。

三者围绕“发现并收服从者”形成基础循环：

```text
探索世界（Map）
      │
      ▼
发现角色 / 事件
      │
      ▼
交流与选择（Dialogue）
      │
      ├── 好感度与关系变化
      ├── 解锁新的角色事件
      └── 产生冲突 / 挑战 / 试炼
                    │
                    ▼
                战斗（Battle）
                    │
                    ▼
          结果返回角色与世界状态
                    │
                    ▼
            满足角色解锁条件
                    │
                    ▼
                获得角色卡
                    │
                    ▼
          从者进入玩家可用角色体系
```

`Map`、`Dialogue` 与 `Battle` 是支持游戏实现的可复用能力，但它们本身不是口袋从者的产品目标。真正的游戏体验来自这些能力之上的角色、关系、世界、事件、成长、收服、故事以及玩家选择。

随着游戏开发推进，应通过真实玩法检验这些模块之间是否能够自然组合，并据此发现 LoomRealm Core 和 `game-libs` 中真正需要调整、补充或抽象的部分。

## 角色卡与收服

角色卡是口袋从者区别于传统宝可梦捕获表现的重要核心元素。

当前概念中，一个角色在世界里首先以独立角色存在。玩家与其建立联系后，通过好感度、对话事件、剧情事件、对战或其他角色条件逐渐推进解锁过程。当角色满足其收服条件时，玩家获得该角色对应的 **角色卡**。

角色卡至少表达以下事实：

- 玩家已经正式收服 / 获得该从者；
- 该从者进入玩家可以组织和使用的角色集合；
- 角色在世界中的关系历史并不会因为获得卡片而失去；
- 后续成长、对话、事件和战斗仍可以继续围绕同一角色发展。

角色卡具体如何表现从者的出场、编队、召回、切换、成长与状态，后续再结合 Battle 和实际 playable slice 继续设计。

现阶段不预设角色卡等同于随机抽卡、商业化卡池或纯收藏图鉴。其首先是“从者被玩家正式获得”的游戏内载体。

## 好感度与角色解锁

好感度是主公与其他角色之间的重要关系维度，但它不应被理解为单纯通过重复送礼堆高的数值条。

当前设计方向是让好感度与真实 RPG 行为共同决定角色关系：

- Dialogue 中的选择可以影响关系；
- 地图事件与角色事件可以改变关系；
- Battle 的挑战、协助或结果可以成为关系条件；
- 某些事件只有达到特定关系阶段后才会出现；
- 角色卡应当由“关系 + 事件条件”共同解锁，而不是只检查一个数值阈值。

因此，一个典型从者的收服过程可以是：

```text
第一次在地图中遇见
        ↓
建立基本认识
        ↓
多次 Dialogue / Event
        ↓
好感度与角色状态发生变化
        ↓
触发专属事件或 Battle
        ↓
完成该角色的解锁条件
        ↓
获得角色卡
```

不同角色可以拥有不同的收服路径：有些角色主要通过交流建立关系，有些角色要求战胜，有些角色需要协助完成事件，也可以存在多种条件组合。

## 核心设计目标

### 1. 建立“主公与从者”的核心幻想

玩家以主公身份进入世界。从者不是无人格的收集物，而是先作为世界中的角色被认识，再逐渐成为玩家可以正式收服和使用的伙伴。

“获得一个新从者”应当既具有收集与成长的满足感，也具有完成一个角色关系阶段的 RPG 意义。

### 2. 保持地图 RPG 为核心体验

游戏继续以俯视角地图探索为主要空间形态。

玩家应能够在地图中自由探索，并能够自然理解道路、障碍、区域边界、建筑、场景入口以及不同地点之间的关系。

地图不只是背景，而应逐步成为承载角色、事件、遭遇、故事、收服与成长的主要游戏空间。

### 3. 让 Dialogue 成为角色关系的主要玩法

Dialogue 不只是文本展示，而应承担认识角色、表达玩家选择、推进好感度、解锁信息、触发角色事件和改变关系状态等职责。

玩家与从者之间的关系必须能够通过具体对话和事件被玩家感知，而不是只在后台增加一个不可见数值。

### 4. 让 Battle 参与角色与世界推进

Battle 应当由探索、遭遇、角色事件、挑战或其他游戏情境自然触发，并在结束后将结果带回 RPG 世界。

战斗可以是角色卡解锁条件的一部分，但不要求所有角色都必须通过“打败后收服”的单一路径获得。

Battle 的结果未来也应能够影响角色状态、好感度、成长和后续事件。

### 5. 让收集建立在角色内容之上

口袋从者保留类似宝可梦的“不断获得新角色”驱动力，但收集对象是具有自身关系、事件与人格表达的从者。

角色卡负责给玩家明确的“已经获得”反馈，而角色内容负责让这张卡具有意义。

### 6. 延续 essentials-v21.1 的视觉与内容基础

PokeMan 初期沿用 `essentials-v21.1` 已有的地图与美术资源，使新游戏能够在一个已经成立的 GBA 风格 RPG 世界基础上开始设计。

现有资源主要作为口袋从者世界的起点，而不是限制。随着游戏内容扩大，可以逐渐形成属于口袋从者自己的区域、角色、美术与世界表达。

### 7. 保留完整 RPG 成长空间

口袋从者的长期目标是形成完整的 RPG 循环，而不仅仅是地图移动、对话或战斗模块的组合演示。

后续游戏体验可以围绕以下方向逐步发展：

- 主公身份与成长；
- 从者收集与培养；
- 好感度与角色关系；
- 角色卡与队伍组织；
- 地图探索；
- NPC / 从者对话；
- 角色事件与世界事件；
- 战斗；
- 区域探索与解锁；
- 世界状态变化；
- 故事推进。

这些能力不要求在第一阶段同时完成，但整体设计应允许它们自然加入，而不改变口袋从者的核心身份。

## 第一阶段体验目标

PokeMan 的第一个 playable slice 应优先证明最核心的产品循环，而不只是证明地图能够运行。

第一阶段目标可以围绕一个具体从者展开：

- 游戏能够作为独立实例进入；
- 玩家以主公身份进入一个完整的 RPG 地图场景；
- 玩家能够自然地进行四方向探索；
- 玩家在地图中发现一个尚未收服的角色；
- 玩家能够与其进行 Dialogue，并通过选择使角色关系发生可观察变化；
- 角色关系可以推进到一个事件或挑战；
- 该流程可以进入 Battle；
- Battle 结果能够返回 RPG 世界并影响角色状态；
- 满足条件后，玩家能够解锁并获得该角色的角色卡；
- 获得角色卡后，该从者成为玩家可用角色体系的一部分。

如果这条链路成立，就形成了口袋从者第一个真正有产品意义的 vertical slice：

```text
Map → Dialogue → Relationship → Event / Battle → Character Card
```

它也会同时真实验证 LoomRealm 的 Map、Dialogue、Battle、Realm State、Frame / Runtime 控制流以及多个 `game-libs` 的组合能力。

## 设计原则

PokeMan 后续设计遵循以下原则：

- **玩家是主公，从者是可被认识、建立关系并最终收服的角色。**
- **从者先是角色，之后才是玩家持有的战斗单位。**
- **角色卡是收服关系的核心载体，而不是一开始就假定为随机抽卡系统。**
- **好感度必须服务于真实角色关系和事件，而不是孤立刷数值。**
- **地图探索是 RPG 世界体验的基础。**
- **Dialogue 服务于角色、关系、事件、选择与世界表达。**
- **Battle 是 RPG 世界中的冲突、挑战与成长机制，而不是孤立小游戏。**
- **收服路径允许由 Dialogue、Event、Battle 和角色专属条件共同构成。**
- **先形成可玩的角色收服循环，再增加复杂系统。**
- **新增能力应服务于真实游戏体验，而不是为了展示技术能力。**
- **通过真实游戏需求验证 LoomRealm Core 与 `game-libs`，而不是围绕框架能力反向设计玩法。**
- **已有资源是起点，不是最终内容边界。**

## 当前非目标

当前阶段不以以下内容作为目标：

- 完整复刻传统宝可梦游戏的全部规则；
- 让玩家直接扮演从者；
- 一开始就完成完整战斗、队伍、属性和成长体系；
- 把所有角色都设计成同一种固定收服流程；
- 现在就确定角色卡的完整编队、召唤或商业化规则；
- 为了 PokeMan 而提前设计与当前游戏体验无关的大量系统；
- 为了抽象而提前把所有 PokeMan 业务能力沉淀为新的 `game-libs`；
- 将 PokeMan 变成单纯的平台、框架验证样例或测试夹具。

PokeMan / 口袋从者首先应该成为一个真正的游戏，然后再逐步扩展为更完整的角色收集 RPG。
